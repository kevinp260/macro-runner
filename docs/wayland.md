# Wayland implementation checkpoints

Phase 1 (#91) validated GNOME 50.1 on Ubuntu 26.04 with a single 1920×1080 monitor and portal-mediated input/capture; phase 2 (#92) centralized the desktop boundary.

Phase 3 (#94) implements a private worker-owned Gio portal connection, explicit host registration, cancellable RemoteDesktop/ScreenCast negotiation and logical-coordinate input primitives. It is not connected to playback yet. The caller must supply an application ID matching its installed desktop file and always close the session. No permission persistence or global shortcuts.

The native input calls use the documented XDG Desktop Portal RemoteDesktop interface. This phase does not translate workflow key names, interpolate pointer motion or interpret physical pixel coordinates; those are integration tasks. A single selected monitor at logical origin is required, but this alone does not prove a single-monitor desktop or 1:1 pixel mapping.

Before enabling workflow execution:
- Connect the authorized PipeWire stream to GStreamer and verify fresh frames and logical/pixel mapping. Fail closed for unsupported display layouts or scaling.
- Connect input and capture to worker-owned execution, including pause/stop, drag/hotkey cleanup, cancellation during portal negotiation and revocation while waiting or actively sending input. Check revocation without depending on further input operations. Do not silently skip ambiguous delivery.
- Provide matching desktop-file identity and optional Linux dependencies; test pipx/deb packaging. Validate real GNOME permission dialogs and cleanup.
- Keep window targeting, Wait for Window, global hotkeys and recording deferred on Wayland. Existing legacy paths stay unchanged.

Tests use a fake portal with no native input. They do not establish real compositor behavior. Follow local-testing.md; hosted Actions remain disabled.

Phase 4 (#96) adds the authorized PipeWire FD and GStreamer capture adapter. Use a capture owner with the portal session on the same worker; release input and close the portal before potentially blocking pipeline teardown. Appsink keeps at most one queued sample. Screenshots require increasing running-time timestamps, no older than 500 ms, and (when the pipeline clock is available at call entry) captured at or after the request. No cached frame is returned; an idle compositor that supplies no fresh frame may time out. Frames must exactly match the portal logical size; conflicting metadata, invalid crop bounds or unexpected frame format abort capture and invalidate the combined session. No multi-monitor or scaled coordinate support is claimed. Verify actual display topology separately before activating playback.

Linux runtime requirements for capture: system Python GI bindings (python3-gi), gir1.2-gstreamer-1.0, gir1.2-gst-plugins-base-1.0, gstreamer1.0-pipewire and the GStreamer video conversion plugin (gstreamer1.0-plugins-base). Existing Pillow is reused. No new mandatory pip dependencies. The tested PipeWire 1.6.2 plugin duplicates the supplied FD internally (gstpipewirecore.c); the capture adapter owns the original and closes it after pipeline teardown. GStreamer state transitions remain synchronous native calls; verify shutdown on real GNOME, including disconnect and timeout. No capture or input is wired to runtime/UI yet.

Phase 5a (#98): experimental workflow playback, deliberately disabled by default until local compositor safety checks pass. Set MACRORUNNER_WAYLAND_EXPERIMENTAL=1 only for bounded local QA. A matching installed development desktop file with ID io.github.kevinp260.MacroRunner is required. The app checks native Qt Wayland, exactly one screen at origin, 100% scaling and matching portal/frame geometry. Display change invalidates the run; authorization and capture happen on the worker. No automatic minimization on trial runs; ordinary runs have at least three seconds to focus the target after consent. The existing Stop button and GNOME revocation are the only interruption controls; actual stop/revocation latency and held-input cleanup remain release gates.

Supported in the trial: coordinate click/move/drag/scroll, ASCII key names and printable ASCII typing, key chords/hold/release, image/pixel/watch/OCR workflow operations, ordinary flow/wait/file/launch actions. Timed movement requires a previously commanded position (use an immediate move first); no global pointer observation. Pause or a step boundary with held input aborts the run instead of leaving a key or mouse button pressed. A user must not move the pointer or type during execution. No clipboard operations, window targeting/Wait for Window, global recording or global shortcuts for trial workflows. Inspector pickers and independent capture previews remain deferred: read-only editor capture must not request unnecessary input privileges. Real keyboard layout/typing and scrolling direction need GNOME acceptance tests. Session closes and releases inputs before native capture teardown; if compositor revokes, further input is forbidden. A native shutdown stall still needs real testing; no claim of production readiness.

Local trial launch (only after mocked tests pass): use a dedicated venv created with system Python and --system-site-packages, install the project editable, create ~/.local/share/applications/io.github.kevinp260.MacroRunner.desktop with Name=MacroRunner (Wayland trial), Type=Application and Exec pointing to the dedicated venv's macro-runner entrypoint. Set MACRORUNNER_WAYLAND_EXPERIMENTAL=1 and QT_QPA_PLATFORM=wayland for the test process only. Do not modify the normal pipx installation or run existing click-intensive workflows until bounded real desktop acceptance checks pass. Start with a disposable text editor, a 5-second start delay and one literal key chord; use GNOME's stop-sharing/control indicator for revocation. Test permission rejection, UI Stop while waiting, revocation while waiting, and held-input cleanup with a harmless target before expanding to drag, scroll and visual workflows. Do not register global shortcuts.

Phase 5b (#100): editor tools use a separate read-only ScreenCast session for selecting points, pixel colors, screen regions, reference crops, image matching and live OCR/region previews. Point and region selection use a frozen screenshot displayed in a maximized Qt picker; clicks map to the original image pixels, not global cursor position. Only explicitly saved reference crops are written to disk. Test Move uses a separate pointer-only RemoteDesktop grant and verifies monitor/frame geometry before moving; no button or keyboard events. All remain under the experimental opt-in. Preview placement is compositor-controlled, so position the dialog manually outside the monitored area. A new permission prompt per operation is expected. Verify actual GNOME screen-only and pointer-only permission behavior, picker alignment, cancellation/revocation, and preview cleanup before release.

The snapshot picker fits the image to the dialog; coordinates map deterministically to the source pixel grid, but when reduced, individual adjacent source pixels may not all be selectable. Manual X/Y and region values remain editable. OCR close on Wayland is asynchronous while the native worker stops.
